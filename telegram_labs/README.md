# Учебный ежедневник в Telegram

Две самостоятельные лабораторные на одной предметной области. Основной бот —
[@velisbro_study_diary_bot](https://t.me/velisbro_study_diary_bot).

- [ЛР 5](../lab_05): кнопки меню и непосредственная загрузка расписания.
- [ЛР 6](../lab_06): три состояния импорта — расписание, время, подтверждение.
- Общие модули: разбор расписания, SQLite, команды, ежедневная отправка.

## Быстрый запуск на Mac

Открой `start_diary.command` двойным щелчком. При первом запуске вставь новый токен
BotFather в скрытый запрос терминала и нажми Enter. По умолчанию запускается ЛР 6.
Если macOS не открывает файл двойным щелчком, выполни из корня репозитория:

```bash
zsh start_diary.command
```

Токен сохраняется в `telegram_labs/.env` с правами 600. Файл исключён из Git.
Токен, показанный на скриншоте при создании бота, нужно заменить через `/revoke`
в BotFather. Не отправляй новый токен в чат, не помещай его в исходники и отчёт.

## Первый диалог

1. Открой своего бота и отправь `/start`.
2. Бот подключит готовое расписание ИУ5-32Б, покажет текущий день текстом
   и включит ежедневную отправку в **08:00 по Москве**.
3. Для ответа по запросу нажми «Сегодня» или напиши `расписание` либо `сегодня`.
4. Изменить время можно командой `/notify 07:30`, отключить отправку — `/off`.

День ответа определяется по дате отправки запроса в московском часовом поясе.
Если сообщение задержалось до следующего дня, ответ всё равно относится к дню запроса.
Ежедневная рассылка вычисляет текущий день непосредственно при выполнении задания.
При повторном `/start` ранее сохранённые расписание, время и отключение рассылки сохраняются.

Для загрузки другого расписания используй `/upload`. Файл ИУ5-32Б можно получить
через `/template`. В ЛР 6 после загрузки введи время, проверь пример дня и подтверди
сохранение. Весь недельный список доступен отдельной кнопкой «Неделя».

Во время пошагового ввода клавиатура скрыта; получить файл можно командой `/template`.
В ЛР 5 файл сохраняется сразу. Если перед этим не было `/start`, при прямой загрузке
создаётся рассылка на 07:00; при повторной загрузке сохраняется выбранное время.

## Запуск из терминала

Команды из корня репозитория, Python 3.10 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python telegram_labs/launch.py          # ЛР 6, скрытый ввод токена при необходимости
python telegram_labs/launch.py --lab 5  # ЛР 5
```

Останавливай запущенную версию сочетанием Ctrl+C перед запуском другой.
Один токен нельзя одновременно использовать в двух процессах polling.
Повторный ввод токена: `python telegram_labs/launch.py --configure`.

Альтернатива: скопировать `.env.example` в `.env`, заполнить BOT_TOKEN локально,
запустить `python lab_05/main.py` или `python lab_06/main.py`. Можно задавать
`BOT_TOKEN` и `BOT_TIMEZONE` переменными окружения; они приоритетнее `.env`.

## Расписание

Расписание ИУ5-32Б перенесено из трёх скриншотов пользователя. Известная опора:
19–25 октября 2026 — знаменатель, 26 октября – 1 ноября — числитель.
Программа вычисляет чередование относительно понедельника ЧС **2026-10-26**,
включая переход года. Календарная чётность ISO-недели не используется.

В файле 25 строк занятий с пометками ЧС/ЗН/каждую. На неделе ЗН — 18 занятий,
на неделе ЧС — 16. В пятницу — заметка о самостоятельной работе, воскресенье свободно.
Для иностранного языка оставлены обе аудитории, 305х и 211х: выбери свою по подгруппе.
Названия некоторых предметов на скриншоте сокращены; перед сдачей проверь их по ЛК.

Бот принимает **текст и файлы TXT в UTF-8**, до 100 КБ. Автоматического распознавания
фотографий и подключения к ЛК МГТУ нет. Скриншоты уже вручную перенесены в готовый файл.

Формат собственного расписания:

```text
Неделя ЧС: 2026-10-26
Пн | 08:30-10:00 | Математика, лекция | 501 | каждую
Ср | 10:10-11:40 | Электротехника, семинар | 527к | ЗН
Пт | заметка | День самостоятельной работы
```

Поля разделяются `|`. День: Пн–Вс. Время: начало-конец, допустимы дефис и тире.
Неделя: ЧС, ЗН, каждую. Для ЧС/ЗН обязателен понедельник известного числителя.
Если все занятия идут каждую неделю, строку с датой можно не указывать.
Пересекающиеся занятия одной недели не принимаются; при ошибке прежние данные сохраняются.
Новая загрузка целиком заменяет старое расписание конкретного пользователя.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Главное меню, сброс незавершённого диалога |
| `/upload` | Начать загрузку |
| `/template` | Получить файл расписания ИУ5-32Б |
| `/today`, `/tomorrow`, `/week` | Показать занятия |
| `/notify 07:00` | Включить рассылку и изменить время |
| `/off` | Выключить рассылку |
| `/cancel` | Отменить ввод, сохранив прежние данные |
| `/delete confirm` | Удалить свои сохранённые данные и отключить отправку |
| `/help` | Формат и помощь |

Бот обрабатывает только личные чаты. У каждого пользователя отдельное расписание.
Все даты и время по умолчанию в `Europe/Moscow`, независимо от настроек компьютера.

## Ежедневная отправка и сохранение

Проверка каждые 30 секунд. После выбранного времени бот отправляет расписание текущего
дня, включая сообщение об отсутствии пар. Факт отправки сохраняется в SQLite, поэтому
обычный перезапуск не вызывает повтор за тот же день. При сетевой ошибке бот повторяет
попытку; при блокировке пользователем отключает его рассылку. Меню работает отдельно.

После простоя отправляется только текущий день, без сообщений за пропущенные дни.
Если программа включена после выбранного времени, сообщение придёт в течение минуты.
Сохранённые расписания и настройки переживают перезапуск; незавершённый черновик ЛР 6
живёт в памяти и после перезапуска вводится заново.

Нужны интернет и постоянно работающий процесс. Спящий или выключенный Mac сообщения
не отправляет. Для ежедневной работы без компьютера потребуется размещение на сервере.
SQLite-файлы `lab_05/data/diary.sqlite3` и `lab_06/data/diary.sqlite3` раздельны и исключены
из Git. Запускается один экземпляр каждой базы. База хранится локально без шифрования.

Доставка не является строго exactly-once: сбой между отправкой сообщения и записью
отметки в SQLite может дать повтор. Это ограничение обычного Bot API без идемпотентного
ключа отправки; в штатном режиме и при обычном перезапуске повторы исключаются.
Расписание повторяется до новой загрузки: каникулы, переносы пар и конец семестра
автоматически не определяются. Перед каникулами можно отключить рассылку через `/off`.

## Проверка и защита

```bash
python -m pytest lab_05 lab_06 -v
python -m telegram_labs.demo 5
python -m telegram_labs.demo 6
```

Тесты работают без токена и сети: диспетчер python-telegram-bot настоящий, ответы Bot API
подменены локальным транспортом. Это проверка обработчиков, а не доказательство доставки
в Telegram. Журналы находятся в `lab_05/results` и `lab_06/results`.
В папках обеих работ находятся `report.docx`, `report.pdf` и `report.md` с реальными
экранными формами Telegram. Использован предоставленный титульник, проверяющий —
Гапанюк Ю. Е. Старые отчёты по тестированию и Factory Method доступны в истории Git.
Повторный экспорт DOCX: `python tools/export_bot_reports.py --template /path/to/title.docx`
в среде с python-docx, lxml и Pillow. PDF создаётся из DOCX с проверкой вёрстки.
