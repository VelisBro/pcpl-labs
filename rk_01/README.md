```bash
python3 rk_01/main.py
```

## Модель данных

- `MusicalWork`: ID, название, длительность в минутах, ID основного оркестра.
- `Orchestra`: ID и название.
- `WorkOrchestra`: ID произведения и ID оркестра для отношения M:N.

Создаются 4 произведения, 3 оркестра и 5 связей. Идентификаторы согласованы.
Длительности и распределение репертуара — учебные данные. Длительность хранится
как количественный признак по общему требованию задания; Б2 подсчитывает записи.

## Запросы

| Запрос | Связь | Результат |
|---|---|---|
| Б1 | 1:N | Все пары «произведение — основной оркестр», по названию произведения |
| Б2 | 1:N | Все оркестры с количеством произведений, по возрастанию количества |
| Б3 | M:N | Произведения с окончанием «ов» и списки исполняющих их оркестров |

«Сотрудник», «отдел» и «фамилия» из примера заменены произведением, оркестром
и названием произведения. В Б3 окончание «ов» сохранено: подходят «Вальс цветов»
и «Танец эльфов». Проверка окончания не зависит от регистра.

В Б2 при равном количестве используется название оркестра; пустой оркестр
получает 0. Все соединения используют ID, поэтому одинаковые названия не
смешивают записи. В Б3 произведение без связей получает пустой список оркестров.
Применены list comprehensions, генераторы, `sorted`, `sum`, `any`, `lambda`.

## Результаты и защита

Б2: Камерный — 1, Филармонический — 1, Симфонический — 2.
В Б3 у «Вальса цветов» два оркестра: Симфонический и Камерный.
В Б1 у этого произведения только основной Симфонический оркестр.
Это демонстрирует различие между 1:N и M:N.

Шесть тестов проверяют точные результаты запросов, пустые коллекции и оркестр,
разные ID при одинаковых названиях, регистр и отсутствие связей.
